# 冲刺路线：四个模块拼成“动态避障机器人”

## 1. 为什么是这四条线

任务书给了 8 章 × 3 级。全铺开做不完，也不加分——评的是**选型理由、实现质量、
验证数据**。选这四个，是因为它们沿“感知 → 表示 → 理解 → 规划”形成一条闭环，
且能直接拼成期末“动态避障机器人”：

```text
线性表（环形缓冲）──命中/未命中──► 数组（占据栅格）──► 图（A*/Dijkstra）
        │                                   ▲                    │
        └──────────────► 树（KD-Tree 聚类）─┘                    ▼
                                                          速度指令（10 Hz）
```

| 模块 | 对应章节 / 级别 | 本项目交付 | 为什么选它 |
|---|---|---|---|
| 环形缓冲 `ds/ring_buffer.py` | 线性表 · 基础级 | 最近 N 帧扫描缓存 + 丢帧统计 | 所有上层算法的输入层；顺带给出“主循环是否跟得上”的证据 |
| 栅格地图 `ds/grid_map.py` + `ds/mapping.py` | 数组 · 基础级 + 进阶级 | 二维数组地图、射线写入、膨胀、YAML/PGM 读写 | 规划的空间载体；落盘契约与验收直接相关 |
| KD-Tree `ds/kdtree.py` | 树 · 进阶级 | 建树、KNN、半径查询、欧氏聚类 | 让“障碍物”从点变成簇，支撑动态避障 |
| 图搜索 `ds/astar.py` | 图 · 基础级 + 进阶级 | Dijkstra 与 A* 同框架实现 + 对拍 | 期末主线的核心；两份算法天然可对比性能 |

**暂不做**（报告里说明取舍即可）：栈/队列、串、查找、排序。它们是独立场景，
无法在四周内同时做深；若后续有余力，优先补“优先队列调度”（与现有导航抢任务）
和“哈希表地标”（回环点）。

## 2. 三级难度怎么落

| 模块 | 基础级（必须交） | 进阶级（默认目标） | 挑战级（拉伸） |
|---|---|---|---|
| 线性表 | 定长环形缓冲、FIFO 覆盖 | 加丢帧/延迟统计，接主循环 | 自适应压缩（如按角度量化 + 差分） |
| 数组 | 二维栅格、占据/空闲/未知 | 在线射线建图 + 膨胀 + 标准地图读写 | 多层地图 / 广义表嵌套 |
| 树 | — | KD-Tree KNN + 欧氏聚类 | 动态场景理解（簇跟踪 + 行为参数调整） |
| 图 | Dijkstra 最短路 | A* + 与 Dijkstra 的节点数/耗时对比 | D* Lite 或 RRT* 实时重规划 |

> 冲刺路线 = **每模块进阶级 + 期末进阶级**；挑战级只选 1 个（建议 D* Lite 或簇跟踪），
> 做不完就写进“未完成与原因”，不算失败。

## 3. 期末综合怎么由模块拼成

| 期末档位 | 需要什么 | 当前状态 |
|---|---|---|
| 基础级：定点导航 | 建图 + A* + 路径跟随（mock 已通） | ✅ mock 三目标 |
| 进阶级：动态避障 | 稳定重规划 + 动态障碍（簇检测/减速/绕行）+ 真车 | ⏳ 重规划已有；动态障碍待加 |
| 挑战级：自主探索建图 | 前沿点选择 + 回环 + 返航 | 不做，作为报告展望 |

“动态障碍”在 mock 里的最小实现：在场景里人为注入一个移动点（或让小车把
“未在静态地图中的簇”当作动态障碍），触发局部绕行并记录重规划次数。
真车上则用真人走动复现。

## 5. Sim2Real 对比怎么设计

同一套代码、同一组目标点，在三个环境各跑 N=5 次，记录同一张表：

| 指标 | mock | 仿真 | 真车 |
|---|---|---|---|
| 到达率 | | | |
| 平均用时 / 路径长度 | | | |
| 终点误差 | | | |
| 重规划次数 | | | |
| 地图占据格比例 / 假墙数 | | | |
| `/scan` 帧率与延迟 | | | |

**分析模板**：先列差异 → 按“感知（延迟/噪声）、执行（打滑/惯性）、算法（阈值过拟合
mock）”三类归因 → 每条给一个可验证的修改 → 重跑 → 记录改善幅度。这才是任务书要的
“闭环迭代”，比多写一个模块更值分。
