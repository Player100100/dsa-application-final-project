# 模块规格 · 环形缓冲（线性表）

文件：[03_代码/ds/ring_buffer.py](../03_代码/ds/ring_buffer.py)
对应任务书：线性表 → 传感器数据流管理 → **基础级**（进阶级另做轨迹链表，未实现）

## 目标

以固定容量缓存最近 N 帧 `/scan`，写满后覆盖最旧帧；提供丢帧统计，
作为“主循环是否跟得上”的量化证据。

## 数据结构

定长 `list` + 写指针 `head` + 当前长度 `size`。

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `append` | O(1) | 写 `head`，覆盖时 `dropped += 1` |
| `newest` | O(1) | — |
| `latest(n)` | O(n) | 按时间顺序复制，n ≤ 容量 |
| `snapshot` | O(n) | 全量副本 |

为什么不用 `collections.deque`：课程要求自己实现；且这里需要 `dropped`
与按时间序取最近 n 帧的语义，自己写更清楚。

## 接口

```python
buf = RingBuffer(capacity=10)
buf.append(frame)          # 满了自动覆盖
buf.newest()               # 最新一帧 / None
buf.latest(3)              # 最近 3 帧，旧→新
buf.snapshot()             # 全部，旧→新
buf.dropped                # 被覆盖帧数
buf.total_appended         # 累计写入
```

## 关键决策

1. **只做定长覆盖**，不自动扩容——传感器流的价值在“最近”，扩容只会掩盖主循环变慢；
2. **统计与内容分离**：`clear()` 不清零 `dropped/total`，便于整场实验累计；
3. 存原始帧对象，不做深拷贝——帧是只读快照，上层不得修改。

## 验收

- 单测：`tests/test_ring_buffer.py`（6 个用例：覆盖顺序、latest/newest/oldest、
  清空保留容量、非法容量、环绕顺序）；
- 实战：`nav_demo` 结束时打印 `累计 N 帧，覆盖丢弃 M 帧`；
  mock 10 Hz 下 M ≈ N−10，属正常（容量 10）。

## 局限与下一步

- 只覆盖了基础级；进阶级的“双向链表轨迹点（回环插入/轨迹简化）”未做；
- 若做挑战级压缩，应在本模块外另开 `ds/compression.py`，不把压缩逻辑塞进缓冲区。
