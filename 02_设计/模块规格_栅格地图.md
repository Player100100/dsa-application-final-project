# 模块规格 · 二维占据栅格（数组）

文件：[03_代码/ds/grid_map.py](../03_代码/ds/grid_map.py)、
[03_代码/ds/mapping.py](../03_代码/ds/mapping.py)
对应任务书：数组和广义表 → 环境表示与地图建模 → **基础级 + 进阶级**

## 目标

用二维数组表示环境：`-1` 未知、`0` 空闲、`1..100` 占据程度；支持在线激光建图、
障碍膨胀、以及 ROS 2 标准 YAML+PGM 读写。

## 数据结构

一维 `list[int]` 按行主序存 `width × height`，索引进制 `idx = y*width + x`。

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `get/set` | O(1) | 边界与取值校验 |
| `world_to_cell` | O(1) | 向下取整；允许越界，由调用方判断 |
| `inflated_mask` | O(占据格数 × r²) | 欧氏半径膨胀，输出布尔阻挡表 |
| `save/load` | O(w·h) | trinary 三值落盘 / 读回 |
| `ScanMapper.update` | O(射线数 × 射线长度) | Bresenham；1080 束取 stride=4 后约 4.3 ms |

## 栅格更新规则

每束有效回波：起点到端点之间记 `misses += 1`，端点记 `hits += 1`。
输出时：

- `hits ≥ 2 且 hits ≥ misses` → `OCCUPIED(100)`；
- `misses ≥ 2` → `FREE(0)`；
- 其余 → `UNKNOWN(-1)`。

这样一帧的偶发噪点不会立刻变成墙。

## 落盘契约（验收相关，别改）

- `save()` 固定写 `mode: trinary`、`occupied_thresh=0.65`、`free_thresh=0.196`；
- 内部 20–64 的中间值落盘为灰度 205，读回变成 `-1`（未知）；
- PGM 第 0 行是**地图最上面一行**（写盘时翻转行），读回时再翻回来；
- `origin` 按 ROS 规范写占位值，本模块不管理世界原点。

读图时另有一个坑：若 YAML 的 `free_thresh > 0.196`，灰度 205 的“未知”像素
（占用度 0.196）会被判成“空闲”。课程仿真器自带的 7 张地图正是
`free_thresh: 0.25`——实测同一张 `maze_3_6x6`：按 YAML 读**未知 0.0%**，
强制 `free_thresh=0.196` 后**未知 2.3%**。`GridMap.load()` 遇到这种情况会发
`RuntimeWarning`，并支持显式覆盖：

```python
grid = GridMap.load("maze_3_6x6.yaml", free_thresh=0.196)
```

## 关键决策

1. **自己实现容器**而不是包厂商的 `GridMap`：数组章节要求本体实现；
   落盘格式对齐 ROS，保证验收方能直接 `load()`。
2. 计数版而非对数几率版：任务只要求三态语义，计数更容易解释、也更好写单测；
   若要概率地图，可把 `hits/misses` 换成 log-odds，接口不变。
3. 射线用 Bresenham（整数栅格直线），避免浮点步进累积误差。

## 验收

- 单测：`tests/test_grid_map.py`（7 个：默认未知、边界/取值、世界↔格心、
  膨胀、三值往返、PGM 行翻转、free_thresh 警告与覆盖）；
- 实战：`nav_demo` 最终地图 `未知 ~44% / 空闲 ~55% / 占据 ~2%`（mock 8×8 m 局部图）。
