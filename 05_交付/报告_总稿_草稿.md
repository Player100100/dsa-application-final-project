## 摘要

本项目以 ROSMASTER X3 仿真小车为平台，用四类自己实现的数据结构串起“感知—表示—
理解—规划”闭环：定长环形缓冲管理激光帧，二维数组维护占据栅格，KD-Tree 做点云
聚类与动态障碍判定，Dijkstra/A* 在网格图上规划路径。算法核心只依赖 Python 标准库，
在 mock、Gazebo 仿真两级环境中验证；在 `maze_1_6x5` 上完成 3 目标 × 5 次 ×
ideal/stress 共 30 次运行，**30/30 到达**；真实地图上 A* 展开节点为 Dijkstra 的
**7.2%**，路径代价一致。Gazebo 中放入真实移动箱子后，系统能检测动态障碍、减速让行，
平均用时由 12.1 s 增至 21.5 s 但 3/3 到达。

## 2 数据结构选型与设计

### 2.1 环形缓冲（线性表）

- **结构**：定长 `list` + 写指针 + 当前长度；
- **操作**：`append`/`newest` O(1)，`latest(n)`/`snapshot` O(n)；
- **为什么不用链表**：传感器流只追加、只取最近，没有中间增删；定长数组 + 下标
  缓存局部性更好；
- **统计**：`dropped` 记录被覆盖帧数，用于判断主循环是否跟得上；
- **单测**：6 个（覆盖顺序、环绕、清空、非法容量）。

### 2.2 二维占据栅格（数组）

- **结构**：一维 `list[int]` 按行主序，`idx = y*width + x`；`(0,0)` 左下；
- **值**：`-1` 未知、`0` 空闲、`1..100` 占据程度；
- **建图**：每束激光用 Bresenham 画射线，中间格 `misses += 1`，端点 `hits += 1`；
  输出时 `hits ≥ 2 且 hits ≥ misses` 判占据，`misses ≥ 2` 判空闲；
- **膨胀**：圆盘近似，给规划留车体半径；
- **落盘**：`save()` 固定 `mode: trinary`、`occupied_thresh=0.65`、
  `free_thresh=0.196`，中间值 20–64 落盘变未知；
- **坑**：课程给的地图写 `free_thresh: 0.25`，灰色未知（占用度 0.196）会被
  读成空闲；`load(..., free_thresh=0.196)` 可覆盖，并对过大阈值发 `RuntimeWarning`；
- **单测**：7 个（含 PGM 行翻转、阈值警告）。

### 2.3 KD-Tree（树）

- **建树**：按 `depth % dim` 轴取中位数切分，O(n log n)；
- **查询**：KNN 用最大堆，半径查询按轴距平方剪枝；
- **聚类**：半径查询 + BFS 连通分量，O(n log n + 邻边数)；
- **选型理由**：点云每帧重建、用完即弃，静态树足够；纯 Python 不引 numpy；
- **实测**：5000 点 / 200 次 k=5 查询，KD-Tree 8.8 ms vs 暴力 973.3 ms（111×）；
  但**聚类只有 1.5×**——Python 递归常数吃掉算法优势，报告如实写；
- **单测**：7 个（与暴力对拍、半径、空树、两团、min_points）。

### 2.4 Dijkstra 与 A*（图）

- **同一内核**：`heapq` 开放集、`dict` g/parent、`set` closed；A* 只把启发式
  从 0 换成 octile，保证两者可直接对拍；
- **八邻域**：直行 1、对角 √2；**禁止斜穿障碍拐角**（两个正交邻格都要可走）；
- **一致启发式**：octile 在八邻域单位代价下一致 → A* 最优且展开 ≤ Dijkstra；
- **恢复策略**：规划失败时降膨胀 → 起点 3×3 解阻 → 沿用旧路径 2.5 s；
- **实测（合成）**：160×160、18% 障碍，A* 34.0 ms / 6733 节点，
  Dijkstra 86.4 ms / 21121 节点（31.9%），代价一致；
- **实测（真实 live map）**：10 张图，A* 41 节点 / 0.3 ms，Dijkstra 566 节点 /
  2.3 ms（7.2%），路径代价 2.00 m 完全一致；
- **单测**：13 个（含清角、无解、未知区、膨胀、起点解阻）。

### 2.5 跨帧簇跟踪（树的应用延伸）

- **输入**：每帧车体系点 + KD-Tree 聚类结果；
- **关联**：最近质心 + 门限 0.5 m，速度低通；
- **动态判据**：连续 ≥3 帧、速度 ≥0.25 m/s；
- **关键坑**：必须在**世界坐标**跟踪。车体系下静止墙会因自车运动产生约
  −0.18 m/s 表观速度，mock 里误报 `动2/动3`；转世界后误报降到偶发 0–1；
- **单测**：7 个（静止/移动/门限/过期/前方/后方/平滑）。

## 3 实现

### 3.1 分层

```text
demo/       nav_demo（建图→规划→10Hz 控制）、bench、bench_real_map、bench_cluster_real
ds/         ring_buffer / grid_map / mapping / kdtree / astar / cluster_tracker
robot_io    唯一接触厂商 SDK 的适配层（mock / 仿真 / 真车）
外部        rosbridge → Gazebo 或真车
```

`ds/` 不 import `robot_io`，可脱离机器人单测；核心算法零第三方依赖。

### 3.2 主循环（10 Hz）

```text
/scan → RingBuffer → ScanMapper（Bresenham）→ GridMap
                                   │ 每 0.8 s
                         inflated_mask → A* → smooth_path → 纯追踪 → /cmd_vel
/scan → 车体系点 → KDTree → 簇 → 世界坐标跟踪 → 动态判定 → 减速/让行
```

时间预算（mock 实测）：建图 4.3 ms + 聚类约 15 ms，10 Hz（100 ms）有余量；
A* 单次 1.9 ms（296 节点）。真车 `/scan` 6.5–7.2 Hz，更宽松。

### 3.3 控制与安全

- 远端看门狗 0.5 s，必须 ≥10 Hz 连续发速度；
- 纯追踪前视 0.30–0.45 m；航向死区 0.06 rad，降增益减少窄道摆头；
- 安全层：前向 0.18 m 硬停 + 0.45 s 保持；贴脸“转-退”交替；2 s 没挪窝倒车；
- 动态障碍：1 m 内减速 60%，0.6 m 内停车 0.5 s 并反侧转。

### 3.4 地图交付

`GridMap.save()` 是唯一交付动作，磁盘上只有 `-1/0/100`；
厂商 `rosmaster_gridmap.GridMap.load()` 能直接读本项目的产物（实测值域仅三值）。

### 3.5 实验工具链

- `scripts/check_sim.py`：TCP → WebSocket → SDK → 首帧 → TF 分层预检，
  `--expect-origin` 校验仿真是否重置；
- `scripts/start_sim_stack.ps1`：一键起 VM + Gazebo + rosbridge，支持
  `-Maze1`/`-Maze1Stress`/`-Ideal`/`-Empty`/`-Stop`；
- `scripts/vm/`：虚拟机侧脚本（原子重启、清理、UDP-only DDS、动态箱子）。

### 4.2 基线（3 目标 × 5 次 × ideal/stress）

| 目标 | ideal | stress |
|---|---:|---:|
| (0.5,0) | 5/5，2.08 s | 5/5，2.10 s |
| (1.0,0) | 5/5，5.76 s | 5/5，5.86 s |

### 4.3 规划

- 真实 live map：A* 41 节点 vs Dijkstra 566（7.2%），0.3 vs 2.3 ms，代价一致；
- 9 组分辨率 × 膨胀全部到达（12.0–12.7 s），默认 0.05 m / 0.15 m。

Gazebo `empty_world` 放 0.2×0.2×0.4 m 箱子，约 0.6 m/s 横穿，目标 (2,0)：

| 场景 | 到达 | 平均用时 | 重规划 |
|---|---:|---:|---:|
| 无箱子 | 3/3 | 12.1 s | 14 |
| 箱子横穿 | 3/3 | 21.5 s | 30 |

`动N` 在箱子经过车头时出现，减速/让行后仍到达。

## 5 Sim2Real 分析

### 5.1 ideal vs stress

同一套代码、同一目标，stress 只慢 1–6%，到达率相同。说明在**可通行走廊**里，
当前算法对打滑不敏感；瓶颈不在控制增益。

### 5.2 环境/几何差异

`maze_3_6x6` 的第一个窄口连 ideal 和 ground truth 里程计都过不去；换
`maze_1_6x5` 后 ideal/stress 都能到达。结论是**车体/窄口几何**问题，
不是算法或里程计；这一条作为环境差异保留，不通过调参掩盖。

### 5.3 静态地图对齐

5 张 maze_1 live map 与课程 YAML：原始重合 60.7%，最佳平移 1 格（0.05 m）
后 85.4%。说明是**一格原点/格子中心约定差**，校正后仍有约 15% 漏墙/薄墙；
目标点应以 live map 为准。

### 5.4 基础设施对实验的影响

批量实验暴露过：4 GB OOM、FastDDS SHM 残留、`rosapi_node` 泄漏、
批处理子进程残留。这些都通过 6 GB、UDP-only profile、原子重启与
`--expect-origin` 解决；未解决前的 `INFRA` 行全部剔除并重跑。

## 6 结论与局限

### 6.1 结论

1. 四类数据结构可以拼成完整导航闭环，核心算法零第三方依赖；
2. 真实地图上 A* 相对 Dijkstra 展开节点降一个数量级，代价不变；
3. ideal/stress 30/30 到达，动态障碍能被检测并影响控制；
4. 主要失败来自几何（窄口）与基础设施，不是数据结构选型。

### 6.2 局限

- 未做 SLAM / 回环 / 全局定位，只靠轮式里程计 + 局部地图；
- 动态障碍只测了一个箱子、一个方向；未做动态重规划（D* Lite）；
- 聚类参数只标定了一帧、一个位置；
- 真车数据缺失；
- 未做章节（栈/串/查找/排序）只在本文说明取舍，没有实现。

### 6.3 如果继续

- 动态：Gazebo actor 多方向 + D* Lite/RRT* 重规划；
- 感知：多帧点云地图拼接、假墙统计；
- 真车：同目标 5 次，补三环境对比；
- 课程章节：优先补“优先队列调度”（与导航抢任务）和“哈希表地标”。
