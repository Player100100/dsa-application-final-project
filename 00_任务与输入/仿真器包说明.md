# 仿真器包说明（ros2-masterX3）

> 位置：`F:\数据结构与算法应用\仿真器等2项文件\仿真器\仿真器\`
> 来源：课程/学校发放的「无小车时的替代方案」。包内 `使用说明.md` 只有三句话，
> 本文是把它的实际内容、导入方式和接入本项目的方法补全。

## 1. 包里有什么

| 文件/目录 | 作用 |
|---|---|
| `simulator/ros2-masterX3.ovf` | 虚拟机描述（**用 VMware Workstation 打开它**） |
| `simulator/ros2-masterX3-disk1.vmdk` | 系统盘，约 9.45 GB（流优化格式），导入后最大 50 GB |
| `simulator/ros2-masterX3.mf` | SHA256 校验值 |
| `maps/maps/*.yaml + .pgm` | 7 张内置地图的**客户端可加载版本**（与仿真内置地图对应） |
| `VMware-workstation-full-17.6.4-...exe` | VMware 安装包；**本机已装 25.0.0，不需要再装** |
| `1.png` | 官方导入示意：右键 `.ovf` →「VMware Workstation」 |

OVF 元数据（已读）：

- 名称 `ros2-masterX3`，Ubuntu 64 位，虚拟机硬件版本 vmx-21；
- **8 vCPU / 8192 MB 内存 / 50 GB 磁盘**；
- 网卡 E1000，接在 **`nat` 网络**（对应本机 VMnet8，`192.168.150.x`）；
- 注释原文：「该虚拟机是为了服务于学生端。主要目的是使学生可以无学习成本地使用上 Gazebo 仿真」。

## 2. 怎么导入（两种方式，选一种）

### 方式 A：图形界面（官方做法）

1. 打开 VMware Workstation；
2. 「文件 → 打开」，选 `simulator\ros2-masterX3.ovf`；
   或按 `1.png` 那样右键 `.ovf` →「打开方式 → VMware Workstation」；
3. 选择存放位置（**建议 F 盘，至少留 50 GB**；C 盘只剩约 42 GB，不要放 C）；
4. 等待导入完成（9.4 GB 盘转换需要几分钟）；
5. 启动虚拟机，按提示登录。

### 方式 B：命令行（已用这条）

```powershell
$ovftool = "C:\Program Files (x86)\VMware\VMware Workstation\ovftool\ovftool.exe"
& $ovftool --lax --allowExtraConfig `
  "F:\数据结构与算法应用\仿真器等2项文件\仿真器\仿真器\simulator\ros2-masterX3.ovf" `
  "F:\数据结构与算法应用\仿真器等2项文件\仿真器\VM\ros2-masterX3\ros2-masterX3.vmx"
```

导入完成后得到 `...\VM\ros2-masterX3\ros2-masterX3.vmx`，双击即可启动。

> ⚠️ **本机实测的坑**：`ovftool 5.0` 会把 `virtualhw.version` 写成 `"99"`，
> Workstation 25 启动时报 “hardware version is not supported”。把 VMX 改成
> `virtualhw.version = "21"`（OVF 原始值 `vmx-21`）即可。导入后本机还把它
> 调到 **4 vCPU / 6 GB**（宿主 15.7 GB；4 GB 会 OOM，见实验记录 §8）。

### 启动、截图与关机（可脚本化）

```powershell
$vmrun = "C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe"
$vmx   = "F:\数据结构与算法应用\仿真器等2项文件\仿真器\VM\ros2-masterX3\ros2-masterX3.vmx"

& $vmrun -T ws start $vmx gui          # 有界面启动（首次建议）
& $vmrun -T ws captureScreen $vmx "F:\数据结构与算法应用\仿真器等2项文件\仿真器\VM\boot.png"
& $vmrun -T ws stop $vmx soft          # 正常关机
```

`captureScreen` 不需要进系统，可以看到登录界面/桌面，用来判断是否自动登录。
首次开机 1–2 分钟；若停在登录界面，就需要课程方给的账号密码。

项目里另有脚本（`start_sim_stack.ps1` 会连仿真和 rosbridge 一起拉起来）：

```powershell
cd 03_代码
powershell -ExecutionPolicy Bypass -File scripts\start_sim_stack.ps1          # VM + Gazebo + rosbridge
powershell -ExecutionPolicy Bypass -File scripts\start_sim_stack.ps1 -Ideal   # ideal 模型
powershell -ExecutionPolicy Bypass -File scripts\start_sim_stack.ps1 -Stop    # 停仿真并关机

# 只想开 VM、不启仿真：
powershell -ExecutionPolicy Bypass -File scripts\start_sim_vm.ps1 -Gui
```

> 包内是 **OVF + 独立 VMDK**，不是单文件 OVA，所以必须保留
> `ros2-masterX3.ovf`、`ros2-masterX3-disk1.vmdk`、`ros2-masterX3.mf` 在同一目录。

## 3. 启动后要拿到的三样东西

1. **登录账号密码**：包里没有写，问课程方/同学；若虚拟机自动登录，直接看桌面；
2. **仿真启动方式**：桌面快捷方式、`~/` 下的脚本或 `ros2 launch` 命令
   （在虚拟机里 `ls ~`、看桌面图标、`history` 都能找到）；
3. **虚拟机 IP**：`hostname -I`，NAT 下通常是 `192.168.150.x`。

拿到后按 [仿真环境接入.md](仿真环境接入.md) 做：

```powershell
cd 03_代码
..\.venv\Scripts\python scripts\check_sim.py --ip 192.168.150.x
```

不想进虚拟机查 IP 的话，可以读 VMware 的 DHCP 租约：

```powershell
python scripts\find_vm_ip.py --vmx "F:\...\VM\ros2-masterX3\ros2-masterX3.vmx"
```

## 4. 地图文件（maps/）

7 张：`cafe`、`laberinto_1`、`laberinto_simple`、`maze_1_6x5`、`maze_2_6x5`、
`maze_3_6x6`、`maze_4_metal_6x6`（包内 README 提到的 `*_victimas` 变体在本包里没有）。

按 `free_thresh=0.196` 读入后的实测尺寸（可用于选目标点）：

| 地图 | 尺寸（格） | 实际大小 | 占据 | 未知 |
|---|---|---:|---:|---:|
| cafe | 190×449 | 9.5×22.5 m | 3.4% | 8.6% |
| laberinto_1 | 117×117 | 5.9×5.9 m | 19.6% | 6.9% |
| laberinto_simple | 119×119 | 6.0×6.0 m | 7.0% | 3.1% |
| maze_1_6x5 | 122×101 | 6.1×5.1 m | 11.0% | 0.9% |
| maze_2_6x5 | 121×101 | 6.1×5.1 m | 10.5% | 0.7% |
| maze_3_6x6 | 122×123 | 6.1×6.2 m | 10.3% | 2.3% |
| maze_4_metal_6x6 | 122×123 | 6.1×6.2 m | 10.0% | 2.3% |

> 我们的 `nav_demo` 目前固定建 8×8 m 的局部图（原点在启动位置附近），
> 与这些世界坐标地图**不共享原点**。要用内置图做全局对照，需要把
> `origin` 与机器人初始位姿对齐，或把本项目的建图结果与它按位姿拼接——
> 这是 M1 之后的工作，不要直接拿 `nav_demo` 的格子坐标去对这张图。

格式与我们的 `GridMap` 完全兼容：`mode: trinary`、`resolution: 0.05`、
`origin` 为负值、PGM 灰度三值。**一个坑**：这些 YAML 写的是

```yaml
free_thresh: 0.25
```

而灰色未知像素 205 的占用度是 `(255-205)/255 = 0.196 < 0.25`，按 ROS 规则会被
**误判成“空闲”**。实测 `maze_3_6x6`（122×123、0.05 m/格、origin (-2.58, -3.58)）：

| 读法 | 未知 | 空闲 | 占据 |
|---|---:|---:|---:|
| 按 YAML（0.25） | **0.0%** | 89.7% | 10.3% |
| 强制 0.196 | **2.3%** | 87.4% | 10.3% |

本项目 `GridMap.load()` 已支持覆盖，并会在阈值过大时发 `RuntimeWarning`：

```python
from ds.grid_map import GridMap
grid = GridMap.load(r"...\maps\maps\maze_3_6x6.yaml", free_thresh=0.196)
```

## 5. 与本项目的关系

- 仿真器只负责“把车和世界跑起来 + 提供 rosbridge”；算法仍跑在 Windows 上；
- 与真车切换只改 `--ip`，代码不变；
- 课程文档里出现过的 `192.168.143.128`、`192.168.244.131` 是别的机器的 NAT 网段，
  **以你虚拟机 `hostname -I` 为准**。

## 6. 本机已跑通（2026-11-25）

| 项 | 值 |
|---|---|
| 虚拟机位置 | `F:\数据结构与算法应用\仿真器等2项文件\仿真器\VM\ros2-masterX3\` |
| 虚拟机 IP | `192.168.150.131`（NAT，hostname `ros-master-x3`） |
| SSH | `ssh rmsim` 免密（专用密钥 `~/.ssh/rmsim_ed25519`，已写入 `~/.ssh/config`） |
| ROS | Humble，工作空间 `~/Desktop/virtual_car` |
| 启动 | 虚拟机内 `~/sim_start.sh`、`~/bridge_start.sh`；`~/sim_ideal.sh` 是 ideal 参数版 |
| 结果 | 端到端导航成功（ideal 短目标 8.2 s）；详见 [实验记录](../04_实验/2026-11-25_仿真联调.md) |

两个**必须同时满足**的条件（否则雷达全 NaN 或 TF 失败）：

1. 仿真进程要有 X display：`DISPLAY=:0` +
   `XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.*`（Wayland 会话，文件名会变）；
2. rosbridge 启动前要 source 工作空间 `~/Desktop/virtual_car/install/setup.bash`，
   否则 `yahboom_rosmaster_tf` 的 srv 导不进来。

## 7. 已知注意事项

- 虚拟机默认 8 GB 内存，宿主机内存不足时改小（4 GB 也能跑，但 RVIZ/Gazebo 会慢）；
- 包内 README 提到 RVIZ 偶发模型加载错误，重启仿真通常能恢复；
- 首次导入后建议在 VMware 里做一次「快照」，改坏了可回滚；
- 不要把 9090 转发到公网；NAT 足够本机访问。
