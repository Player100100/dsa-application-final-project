# 仿真环境（虚拟机）接入指南

> 目标：让 Windows 上的本项目（以及 AI）能稳定调用虚拟机里的 ROS 2 仿真。
> 本机已确认：**VMware Workstation** 已安装（`vmrun.exe` 可用），
> 网卡 `VMnet8 = 192.168.150.1`（NAT）、`VMnet1 = 192.168.248.1`（仅主机），
> 已存在 SSH 密钥 `~/.ssh/id_ed25519`，WSL2 里有一个已停止的 Ubuntu。

## 0. 先分清两种“调用”

| 层级 | 需要什么 | 能做什么 |
|---|---|---|
| **A. 只连服务**（必须） | Windows 能访问虚拟机的 `IP:9090` | 跑导航、自检、采数据；**不需要进虚拟机** |
| **B. 还能控制虚拟机**（推荐） | 虚拟机开 SSH，Windows 有免密登录 | 启动/停止仿真、看日志、重启 rosbridge、抓包 |

A 是底线；B 让 AI 能自己把环境拉起来、排查问题。**先做 A，再做 B。**

本项目与 ROS 的唯一通道是 **rosbridge 的 WebSocket（默认 9090）**，不是 DDS，
所以不存在跨虚拟机的组播/发现难题，只要 TCP 通即可。

## 1. 网络：让 Windows 能访问虚拟机的 9090

### 1.1 推荐用 VMware NAT（默认）或仅主机

| 模式 | Windows 能看到虚拟机吗 | 说明 |
|---|---|---|
| **NAT（VMnet8，默认）** | ✅ 可以，直接访问 `192.168.150.x` | 最省事；虚拟机也能上网 |
| **仅主机（VMnet1）** | ✅ 可以，`192.168.248.x` | 隔离最好；虚拟机不能上网 |
| 桥接 | ✅ 取决于校园网/路由器 | 虚拟机与 Windows 同网段；校园网可能限制 |
| VirtualBox NAT | ❌ 主机不能主动连 | 需端口转发，或改仅主机/桥接（本机未装 VBox） |

### 1.2 拿虚拟机 IP

在虚拟机里执行：

```bash
hostname -I
# 或
ip -4 addr show | grep inet
```

NAT 模式下通常是 `192.168.150.x`（与本机 VMnet8 同网段）。

### 1.3 确认 rosbridge 监听在所有网卡

```bash
ss -ltnp | grep 9090
```

期望看到 `0.0.0.0:9090` 或 `*:9090`。若是 `127.0.0.1:9090`，Windows 永远连不上：

```bash
# rosbridge_suite 的标准启动方式（课程镜像可能已自带 launch，二选一）
ros2 launch rosbridge_server rosbridge_websocket_launch.xml address:=0.0.0.0 port:=9090
```

### 1.4 虚拟机防火墙

```bash
sudo ufw status
sudo ufw allow 9090/tcp        # 仅当 ufw 处于 active
```

### 1.5 从 Windows 验证

```powershell
Test-NetConnection 192.168.150.128 -Port 9090
```

更完整的一步到位（本项目自带，会依次测 TCP → WebSocket → SDK → 首帧）：

```powershell
cd 03_代码
..\.venv\Scripts\python scripts\check_sim.py --ip 192.168.150.128
```

全部 `[ok]` 后，直接：

```powershell
..\.venv\Scripts\python demo\nav_demo.py --ip 192.168.150.128 --goal 1.5 0.0
```

> 课程文档里的 `192.168.143.128` / `192.168.244.131` 只是样例，
> **每次都以虚拟机里 `hostname -I` 的实际结果为准**；换网络后 IP 可能变。

## 2. 让 AI 能控制虚拟机：SSH 免密

### 2.1 虚拟机里装 SSH 服务

```bash
sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

### 2.2 把 Windows 的公钥装进虚拟机

本机已有 `C:\Users\18640\.ssh\id_ed25519.pub`。在 **Windows PowerShell** 里执行
（把 `用户名` 和 `IP` 换成虚拟机的）：

```powershell
$pub = Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
ssh 用户名@192.168.150.128 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$pub' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

第一次会问密码；之后应免密。

### 2.3 在 Windows 上配一个别名

编辑 `C:\Users\18640\.ssh\config`（没有就新建）：

```sshconfig
Host rmsim
    HostName 192.168.150.128
    User 用户名
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
```

验证：

```bash
ssh rmsim 'hostname; . /opt/ros/humble/setup.bash && ros2 topic list | head -20'
```

> ROS 版本按镜像实际改（Humble / Foxy / Jazzy）。
> **非交互 SSH 不会自动 source 环境**，命令里必须显式 `. /opt/ros/<distro>/setup.bash`，
> 有工作空间再加 `. ~/ros2_ws/install/setup.bash`。

### 2.4 配好之后 AI 能做什么

```bash
ssh rmsim 'hostname -I'                                    # 查 IP
ssh rmsim 'ss -ltnp | grep 9090'                           # 查 rosbridge
ssh rmsim '. /opt/ros/humble/setup.bash && ros2 topic list' # 查话题
ssh rmsim '. /opt/ros/humble/setup.bash && ros2 node list'  # 查节点
ssh rmsim 'tail -n 50 ~/sim.log'                           # 看日志
```

启动仿真需要课程给的 launch 命令，例如（**以课程说明为准**）：

```bash
ssh rmsim '. /opt/ros/humble/setup.bash && nohup ros2 launch <课程包> <文件>.launch.py > ~/sim.log 2>&1 &'
```

## 3. 虚拟机开关机（可选，VMware）

```powershell
$vmrun = "C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe"
& $vmrun list
& $vmrun -T ws start "D:\路径\你的虚拟机.vmx" nogui
& $vmrun -T ws stop  "D:\路径\你的虚拟机.vmx" soft
```

> 不建议用 `runProgramInGuest` 传密码，命令行会留痕；**控制虚拟机内部一律走 SSH**。

## 4. 如果仿真跑在 WSL2 里

- WSL2 默认把服务转发到 Windows 的 `localhost`，rosbridge 起在 WSL 里后，
  Windows 侧直接用 `--ip 127.0.0.1` 即可；
- 若开了“镜像网络模式”，则用 WSL 的 IP（`wsl hostname -I`）；
- 同样确认 rosbridge 监听 `0.0.0.0:9090`，WSL 内不需要额外防火墙配置。

## 5. 排错对照表

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| TCP 不通 | 虚拟机没开 / IP 变了 / 不在同一虚拟网络 | 虚拟机里 `hostname -I`；确认 NAT/仅主机；Windows 看 `ipconfig` 有无 VMnet8 |
| TCP 通，WebSocket 非 101 | 9090 被别的服务占用，或 rosbridge 没起 | `ss -ltnp \| grep 9090`；换端口或重启 rosbridge |
| 预检通过但没有 `/scan` | 仿真节点没启动 / 话题名不同 | `ros2 topic list`；启动课程仿真；必要时在 `robot_io.py` 改话题名 |
| 有 `/scan` 但查变换失败 | `robot_state_publisher` / TF 没起 | 启动完整仿真 launch，不要只起传感器 |
| 昨天能连今天不能 | DHCP 换了 IP | 在 VMware 虚拟网络编辑器里给虚拟机做 DHCP 保留，或虚拟机内设静态 IP |
| 能连但延迟很大 | 虚拟机资源不足 / NAT 拥塞 | 给 VM 至少 2 核 4 GB；关掉宿主机大流量程序 |

## 6. 交给 AI 的最小信息包

配置好后，把下面三样告诉 AI（或写进 `06_进度/下一步.md` 的“环境信息”）：

1. **rosbridge 地址**：`192.168.150.x:9090`；
2. **SSH 别名**：`rmsim`（以及 ROS 发行版、工作空间路径）；
3. **启动仿真的命令**：课程镜像里的 launch 命令原文。

之后 AI 就能自己完成：`check_sim` → 启动仿真 → 跑三目标 → 采数据 → 写实验记录。

## 7. 安全边界

- 虚拟网络保持 **NAT / 仅主机**，不要把 9090 转发到公网或校园网；
- SSH 只用密钥，不在脚本、文档、聊天里写密码；
- 真车与仿真用不同 IP，`nav_demo` 非 mock 启动前会停 3 秒提示；
- 任何会让车/仿真运动的命令，先说明再执行。
